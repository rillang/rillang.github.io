Community and governance

Rill is a young project with a single maintainer. This page says how it is run today and how that is meant to grow.

The governance documents below are proposals awaiting the maintainer's approval. They describe the intended process, not settled policy.

How decisions are made

Changes to the language, the standard library and the tools are written up as RFCs: Markdown documents in the repository, reviewed in a pull request, decided after a final comment period with written reasons. Today the maintainer decides; a path to a core team is written down in advance.

  • The RFC process and the RFC index, with the template
  • Evolution and stability: versions, deprecation, the compatibility promise planned for 1.0
  • How Rust, Go, Python, Swift and Zig do it, and what Rill takes from each

Contributing

Every change starts with a failing golden test, keeps the compiler building itself to a byte-identical fixpoint, and passes rill fmt and rill lsp --check. AI-assisted contributions are welcome under the same rules, with a human who has reviewed them.
