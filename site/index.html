Write what you mean

Enums carry data, switch takes them apart, and the compiler says which case you forgot.

shapes.rl
enum Shape {
  case circle(Float)
  case rect(Float, Float)
  case dot
}

fn area(_ s: Shape) -> Float {
  switch s {
  case .circle(r): return 3.14 * r * r
  case .rect(w, h): return w * h
  }
}
$ rill build shapes.rl
error[E0011]: switch must be exhaustive, missing: .dot
 --> shapes.rl:8:3

One place for patterns

Match arrays by shape, enums by case, structs by field, with where guards. Patterns live in switch, and the compiler checks that every case is covered.

patterns.rl
fn describe(_ xs: [Int]) -> String {
  switch xs {
  case []: return "empty"
  case [x]: return "just $x"
  case [first, ...rest] where first > 100: return "big start, ${rest.len()} more"
  case [first, second, ...]: return "$first, $second, ..."
  }
}
$ rill run patterns.rl
empty | just 7 | big start, 1 more | 1, 2, ...

No null, no exceptions

T? may be missing, T! may fail. ? passes the problem up, ?? supplies a default, and the types tell every caller.

errors.rl
fn parsePort(_ s: String) -> Int! {
  guard let n = s.toInt() else {
    return fail("not a number: $s")
  }
  return n
}

fn config(_ raw: String) -> String! {
  let port = parsePort(raw)?
  return "listening on $port"
}
$ rill run errors.rl
listening on 8080
error: not a number: http

Test it next to the code

Tests live in the same file. rill test also fuzzes and measures coverage.

shapes.rl
test "a rectangle is width times height" {
  expect(area(.rect(2.0, 3.0)) == 6.0)
}
$ rill test shapes.rl
ok    shapes.rl    1 test   0.00s

Use every core

Tasks are green threads on all cores with work stealing. A group waits for its tasks, and tasks cannot race on what they capture: they get copies.

tasks.rl
  let results = Channel<Int>(capacity: 3)
  group {
    for n in [10, 20, 30] {
      spawn { results.send(n * n) }
    }
  }
$ rill run tasks.rl
total 1400

Fast, and you can see why

Ahead-of-time native code, values without hidden aliasing, a parallel collector. Benchmarks (rill test --bench) and CPU and heap profiles (rill pprof) are built in, in Go's pprof format.

bench.rl
bench "split a sentence" {
  let s = strings.repeat("the cat saw the dog ", 100)
  while loop() {
    let _ = words(s)
  }
}

No collector where it matters

Most code is happier with a garbage collector. A render loop, an audio thread or a physics step is not. Mark it nogc and the compiler checks that it never touches the GC heap: memory comes from arenas, pools and fixed arrays, and one simple rule replaces a borrow checker. A value from an arena may not leave its block.

  • nogc on a function, a file or a module: no GC allocation, checked.
  • spawn nogc { … }: a task the collector never stops, for frames without hitches.
  • rill build --nogc: a binary with no collector at all.

planned The design is in RFC 0008; the syntax may still change.

The ground is already there: Rill's heap, garbage collector and scheduler are written in Rill itself, in its unsafe dialect with raw pointers, loads and stores. Today only the runtime may use it; opening it to every program comes with nogc.

engine/physics/solver.rlplanned
nogc // the whole file

pub fn step(_ world: inout World, _ dt: Float) {
  // freed at the end of the block
  arena { a in
    var contacts = a.array<Contact>(capacity: 1024)
    // letting contacts escape is a compile error
    world.collide(into: &contacts)
  }
}
runtime/rt_heap.rltoday
fn setWord(_ base: Int, _ i: Int, _ v: Int) {
  store64(intToPtr(base + 8 * i), v)
}

pub fn setField(_ s: Int, _ off: Int, _ v: Int) {
  store64(intToPtr(s + off), v)
}
